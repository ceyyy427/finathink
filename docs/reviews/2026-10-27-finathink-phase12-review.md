## 审查与修正

独立审查者使用 gpt-6-astra，仅读取代码与隔离临时测试；自行运行阶段门禁 100 项通过。没有发现 Critical，提出三项 Important：

1. `ResearchPlan.validation_spec` 的键值对数组可被构造函数转为对象，绕过原始 JSON 上的证据成员检查。接收器现在先约束 JSON 容器类型，再对规范化的类型结果复查证据与隐私。
2. 两个独立 store 并发接收相同回传，可能在“文件尚未出现”的旧观察后读到队列已完成，误报收据缺失。现在在终态缺失判断前重新打开收据，同时保留真正缺失时的完整性失败。
3. JSON 键里的机器路径、UNC 路径值没有被全部拦截。现在键和值采用相同私有文本检查，并识别 UNC 路径。

指南例子中的 `backtest-acceptance` 是技能 ID，不是路由目的。审查最初列为 Minor；主代理依据其导致主要上手示例始终失败，将其重评为 Important：修正为 `backtest`，并从文档提取示例参数执行合同测试。

## 边界决定

- 保留外部显式交接；未验证自动 Codex、付费模型、供应商 SDK 或全局技能安装。代价是仍需真实外部执行方回传。
- 本阶段不把接收 JSON 算作因子实证；计算交给 Phase 13，生命周期和界面交给 Phase 14/15。代价是中间态先提供后端合同。
- v1 envelope 和旧调用者保持兼容；新增 `evidence:<64hex>` 格式的成员校验由方法适配层负责。代价是直接调用旧 Bridge 的接入方仍负责自己的成员边界。
- 字段缺口允许先规划，计算时明确阻断；不替换换手率或伪造数据。代价是 READY 的方法选择不代表可计算。
- 无方法的上下文字节与旧限制不变；方法模式总预算为 32768 UTF-8 字节。放不下可明确阻断，不隐式裁掉政策或重新优化组合。代价是部分请求需缩小选择。
- 冻结选择指纹、原因、版本与缺口，不逐字保存所有原路由标签。代价是不能仅凭交接包恢复用户最初标签措辞。
- 沿用现有私有原子写入，增加进程中断后的收据恢复；不声称提供额外断电持久性协议。代价是遵循现有写入器的耐久性边界。
- 内容寻址检查普通损坏与错绑，不防本地管理员一致重写全部 JSON 和 SQLite。代价是它不是经过签名的敌对存储服务。
- 不全局重构宽松的 `ResearchPlan` 构造器；新不可信入口严格校验规范化前后数据。代价是其他调用者继续承担各自的输入边界责任。
- 绝对路径样式和凭证别名保守拒绝，包括嵌套字段。代价是歧义的斜杠前缀文字需要改用不透明引用。
- 暂留本阶段忽略目录中的验证证据，供后续已批准阶段恢复和最终发布验收；不打包或推送这些私有文件。代价是少量本地临时空间。
