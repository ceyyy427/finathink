# Phase 19 验收记录

## 已实现

冻结 Python 源码、算法与依赖身份；逐项解释数据、方法、参数、成本、风险、代码条件。对已有报告显式导出 JSON 包，携带数据需勾选，恢复到独立工作区复算确定性数值并保存逐产物回执。旧报告不回填身份，缺依赖、部分覆盖与数值差异分别呈现。

多资产输入复用用户通用 API，不增加供应商 SDK。原快照单位与 EQUITY/ETF 声明直接进入证据：严格共同收益区间、行业/动量暴露、Euler 方差贡献、经验 CVaR、压力网格、bootstrap 均值区间。运行时与安装包共用既有确定性内核。

## 复现与统计口径

模型文字与因子治理复现需要原材料/授权；本轮包只自动复算已覆盖的确定性数值，不能据此声称整份报告相同。代码内容和 Python/numpy/pandas 精确版本均需匹配；这优先避免静默差异，跨版本包可能需要原环境。移动区块不首尾拼接、固定 200 次，端部采样偏差与未经真实市场覆盖率校准在输出和指南中说明。源码未引入新的运行时依赖。

## 整阶段与发布

完整 Python 回归 **1790 通过、1 条件跳过，593.52 秒**，启用了强制浏览器模式。唯一跳过是隔离适配器环境未安装可选 statsmodels；CI 的量化任务单独安装并检验它。

全新 wheel 在外部临时环境完成实际 HTTP、独立 spawn、研究包跨根目录复算、重启和私密备份恢复。Notebook 已执行，锁定依赖安全扫描未发现已知漏洞。初次安装命令使用相对 wheel 路径、Notebook 内核未继承源码路径导致验证命令失败，改用绝对 wheel 路径和显式源码路径后通过；没有因此修改全局 Python 环境。

一次独立整阶段审查使用 gpt-6-astra/high，发现 4 个 Important、1 个 Minor，无 Critical，无未裁定项。数字溢出会中断 HTTP 校验响应，执行者按实际恢复影响升级为 Important，五项纳入同一修复轮：

1. 恢复 B 时 A 的迟到复算不得覆盖当前选择；程序化选择与回调均检查身份。
2. 元数据导出仅使用已验证报告；原快照缺失或超过 5000 行仍可导出缺依赖包，携带数据时保留行数限制。
3. INCLUDED 产物集合与 expected 严格一致，所有覆盖状态在持久化前校验。
4. 数据、代码、输入阻塞时仍保留每项产物状态；原工作流依赖不被空字典覆盖。
5. 过大数字转换为结构化中文 422 校验响应，避免请求连接中断。
