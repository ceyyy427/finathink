# Phase 18 接口与研究质量验收

基线：main `4c3dffc`（Phase 17 PR #18）。本轮使用独立分支 `codex/phase18-interface-quality`，复用已有用户 API、provider 适配器、SQLite 队列、supervisor、spawn worker、调用账本和报告完整性校验。

## 实现与验证

- 数据与模型协议保留坏 JSON、断流、流式响应、超时和大小上限等类型化结果；诊断将尝试/页数收紧到一次，原研究默认行为保持兼容。
- 本地拥有的临时 HTTP 服务运行 34 个成功与故障用例；数据、OpenAI-compatible、DeepSeek-compatible 都走实际传输/解析链。额外 14 个本机角色调用演示三个固定合成样例评分。测试封锁外部 DNS 与网络；本地通过不会晋升用户账号状态。
- 调用前持久登记、当前空间隔离、0600 文件、受控 JSON 导出、50 份详细记录与保留去重摘要；并发同标识只调用一次，中断/重启不自动重发。
- 三个版本化 SAMPLE 样例进入原研究队列；评估冻结输入、材料、规则、工作流、模型映射和预算。原报告/上下文损坏时停止评分。跨空间、未知引用和不同条件不能冒充相同输入的有效比较。
- 分母保留失败，未知调用、无分母、未知用量与费用使用 null，已知零不改写为未知。经理分歧和本次运行证据保留，模型名称不影响评分。
- 蓝白诊断页面提供本地检查、显式用户探测、模型授权与预算、进度/取消、历史/下载和2–4项条件比较。挂载、读取和重启不会创建外部调用。浏览器会话保存请求标识；存储受阻时停用付费动作，仍可运行本地检查。

所有新增模块先出现预期失败再实现。Task 1 定向161通过；Task 2 定向145通过；Task 3 定向79通过。Task 4 API/Node/浏览器最初因缺少接口或模块失败，再逐项跑通。

额外复现并修正：urllib 包装超时被误判为传输错误；会话存储失败后的重试可能绕过标识保存；切换新任务短暂保留旧任务已完成状态；浏览器拒绝 sessionStorage 导致工作区未初始化。均有直接先失败再通过的回归。测试对已有 API 的 tuple 返回值和浏览器原生 CSP 作了正确适配，没有放宽 CSP。

## 技术 UI 审查

以已提交 DESIGN.md 的蓝白系统为准，使用 Impeccable audit 的可访问性、性能、响应式、主题、实现完整性五项审查。检测器仅运行一次：无主要发现，一条半径超出设计尺度的 advisory，已改为已有 radius token。另修正不存在的间距 token、历史选择触控高度与标题间距。

批量检查1440×900、1920×1080、375×812、兼容结果和质量比较截图；单列移动表单、表格局部滚动、原生 details、可见焦点及 reduced-motion 均保留。确认轮覆盖任务切换与中断恢复。

## 依赖发布修复

pip-audit 首轮发现锁文件 Tornado 6.5.10 的3项已知漏洞（CVE-2026-116577、115927、116578），按修复版本更新为6.6.0。官方 [6.6.0 发布说明](https://www.tornadoweb.org/en/stable/releases/v6.6.0.html)确认最低 Python3.11，与项目支持范围一致；依赖审计与 notebook 验证结果随后记录。没有新增产品运行依赖。

发布复查补充：本地服务绑定绕过 HTTPServer 默认反向域名查询，加入 getfqdn 禁用回归，保证本机兼容测试不依赖正向或反向 DNS。损坏的诊断元数据先失败再拒绝导出，不回显污染字段。质量比较显示每个角色的冻结模型映射，选择变化使迟到比较失效；直接 Node 与浏览器回归均先失败再通过。

首轮全量1746通过、1条件跳过、1失败（旧恢复路径的脱敏下载入口被折叠）；保留入口在默认可见位置后，原测试1通过（7.18秒）。本轮没有删减旧恢复断言。第二轮全量1748通过、1条件跳过（548.60秒）。随后增加3项交互回归，进入最终发布门禁。Tornado修复后 pip-audit 无已知漏洞；隔离环境的6.6.0、pip check与实际 notebook 执行均通过，未改动共享 Python 环境。

阅读与切换补充：新增经理分歧时，按内容身份保留原生折叠和键盘焦点；选择历史时，迟到的付费提交不能夺回当前任务；更早的历史读取不能覆盖更新的探测结果。三项均用实际 HTTP 与受控 spawn 先复现，再修正，完整 Phase18 浏览器12通过，Node59通过。
