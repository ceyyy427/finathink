# 阶段 29 研究面板验收

研究面板保存快照、字段附件和已解析的合同。保存时重新构建面板并核对预览指纹。选择面板开展研究时，应用读取原合同，后台 worker 依照同一套时点规则复核。无论用户重新获取行情还是修改连接，已有研究均可按原输入追溯。

| 验收 | 证据 |
| --- | --- |
| 股票 | 通过受控 HTTP 配置、认证、分页、追加行情和读取日历。在恢复出的工作区选择原面板，完成研究发现、后台验证及 HTML 报告。 |
| ETF | 从用户行情、交易规则和净值附件保存面板，再提交相对强弱策略，核对纸面账本和报告。 |
| 财务时滞 | 用原始行情和财务附件验证净资产收益率。逐项断言公告前为空、公告后出现初值、修订后才采用新值。 |
| 限流、错填和重试 | 429 停止本次获取。历史修订拒绝直接追加。缺日历、错单位和过期预览有可读提示。同一保存或提交可安全重试。 |
| 桌面和移动端 | 使用真实 Chromium 从面板入口发起数据请求、预览、保存并提交策略。检查 1440×900、1920×1080、375×812 的布局并保留截图。 |

三条受控 HTTP 场景走真实本地 HTTP 和独立 worker。合成行情和财务记录作为固定比较样本，映射后按用户快照合同走同一流程。测试在 `tests/research/test_saved_panel_journeys.py` 和 `tests/p7_5/test_phase29_browser.py`。

真实用户数据服务状态为 **待验收**。完成时记录返回的数据模式、可用时间、字段覆盖、接口错误和失败后的恢复结果。验收记录仅保存摘要。
