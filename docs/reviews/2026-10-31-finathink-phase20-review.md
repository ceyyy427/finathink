# Phase 20 验收记录

范围：分离样本评估、显式探索审核、冻结成对复跑、轻量历史与本地维护。沿用现有 Python、SQLite、独立 Supervisor/spawn 和蓝白原生工作台，无新增运行时依赖。计划与规格见同日 superpowers 文档。

## 已验证的实现

- 样本规则：17项测试覆盖手算区间、19/20门槛、正均值反例、零/未知、重复/重叠、晚到证据、混合配置/模式/代码/成本、下限和200条上限。
- 真实证据与审核：29项任务门禁通过；包含20次实际结算、重建证明、不可变评估、建议幂等、显式探索批准、历史批准兼容与跨工作区隔离。
- 成对复跑：22项任务门禁通过；实际两个子任务、同输入不同政策、有限差值、回溯标注、中断后显式继续、代码变化拒绝恢复、损坏/取消阻塞与重启。
- 维护与缓存：43项任务门禁通过；水位游标、同时间新增、跨工作区与重启、未知资源、不隐式恢复、TTL/LRU、并发、同大小还原mtime的修改、符号链接和系统目录别名。
- 实际HTTP新增3项通过；POST需要CSRF，GET不排队。前端66项通过，包括迟到响应、程序化选项变化、样本/成对结构校验和目录请求合并；构建成功。
- 原始API/模块缺失的失败记录、逐任务通过记录和基准保存在本计划独有的忽略工作区中。

## UI Audit

保持白色导航、浅蓝背景、原有表单与表格，未引入新的视觉方案。一次机械检测无告警。一次桌面/移动批量检查发现维护指标阅读过长，已在同一修正批次压缩标签/数值布局和时间格式，并扩大移动历史链接触摸区域；确认批次用于验证修改，不反复打磨。

技术检查按有限范围记分：可访问性3/4、性能3/4、响应式3/4、主题4/4、实现完整性4/4，合计17/20。证据包括原生标签/表格、可见焦点、减少动态效果、状态/错误/空态、三种宽度无整页横向溢出，以及共享颜色与间距令牌。这是作者对新增工作区的技术检查，不是全站WCAG认证或真人辅助技术验收。

首轮浏览器覆盖真实20窗口→建议→审批→成对运行→刷新，发现两个旧错误注入用例受并发目录读取和新列表地址影响；以并发去重的失败Node回归修复重复读取，错误用例改到当前入口。预期HTTP503控制台记录单独核对并保存，其余控制台错误仍失败。
