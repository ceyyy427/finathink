# Finathink 下一轮优化方向

日期：2026-10-27。以已合并的 Phase 10–15 为基线。这份路线将已有底座与下一步增强分开；Phase 16 已通过 PR #17 合并；Phase 17 已通过 PR #18 合并；本轮接续 Phase 18 接口与研究质量，Phase 19–20 保持后续顺序。

## 当前基础

已经具备共用工作台、用户数据通用接口、持久任务与独立 worker、多分析师研究、方法交接、受控因子九步验证、范围治理、学习审核、版本化复跑和离线报告。当前能力与证据见 `FINATHINK_CAPABILITY_ASSESSMENT_2026-10-27.md`。

下一步的价值主要在于把这些能力连接得更容易理解、更容易使用，并让验收从工程样例推进到受控的真实输入。

## Phase 16：交互和布局（本轮）

保持蓝白风格，收束宽屏内容宽度；页面轻淡入、搜索弹窗、展开资料、按钮按压有明确反馈。支持键盘、减少动态效果、无脚本阅读与移动宽度。验收使用真实浏览器和可回归的交互路径，不仅检查截图。

## 为什么先做这些

优先改善“接上数据并完成一次研究”，然后证明模型与研究质量，再扩展覆盖面。已经存在的引擎、预算、队列、风控与复盘继续复用；不为新页面另造一套编排或事实源。

数据入口继续由用户提供通用 API 和声明；平台负责连接诊断、清洗验证与研究处理。模型费用、真实数据许可和真实市场校准需要对应的独立证据，不能由离线样例代替。

## 每批共同交付标准

- 能从正常、空、错误和恢复状态走完真实任务，中文说明直接告诉用户下一步。
- 不把缺失值变成零、来源指标变成本地结果、验证运行变成真实结算。
- 测试、审查和可复算证据与功能一起交付；路线状态只在证据达到验收后更新。
- 核心产品指标先建立基线：首次研究完成情况、阻塞后恢复情况、结果可复现情况、证据完整情况、每次研究耗时与实际费用。未收集的数据不填预设提升百分比。
