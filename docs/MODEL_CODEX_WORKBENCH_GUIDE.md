# 模型与 Codex 研究台

研究台逐一列出各角色获准使用的材料、已经发出的调用和返回观察所引用的证据。从工具目录的「研究」打开「模型与 Codex 研究台」，或访问本机路径 `/research/model-workbench`。已发表的量化结果和纸面账本仍可从原研究报告打开。

## 用合成样例走一遍

1. 启动 `finathink`，选择「内置合成样例」和「本地离线研究」。也可换为工作区已保存的行情快照，选择标的与截止日。
2. 填写研究问题，选择「预览研究材料」。逐个查看基本面、技术、情绪、新闻、学习分析师和研究经理的模型、可用材料、证据引用与调用预算。
3. 核对后勾选本次授权并提交。任务记录会显示队列状态、按角色的发送记录、已知用量、待核对观察和原报告入口。刷新页面或重启后，可以从本地任务历史回到同一研究。
4. 选择一项任务，在「Codex 交接」冻结研究方法和证据。可以复制或下载包、手工导入结果，也可以按下文在本机运行 Codex。详情可重开已接受的研究方案与因子提案。

离线样例的外部模型调用数为零。若快照、角色配置、资料或预算发生变化，请重新预览后授权。相同授权重复提交会返回原任务。

## 接入自己的模型

在本机配置自己的模型凭证，在「模型设置」保存兼容类型、HTTPS 地址、模型标识、凭证引用与可选角色映射。选择 OpenAI-compatible 或 DeepSeek-compatible 后，可给技术分析师和研究经理等角色分别指定模型。将环境变量名填入凭证引用字段，密钥值由运行服务的进程读取。保存配置和预览材料均在本地完成。[模型配置与角色材料](PHASE6_MODEL_RESEARCH_GUIDE.md)

允许外部模型的启动方式如下。

```sh
FINAHINKING_OFFLINE=0 finathink
```

在研究台选择已经保存的模型，补充有来源和可用时间的角色摘要。各分析师只接收该角色可用的材料，经理还会收到本次通过校验的分析师观察。预览列出这项动态输入和预计调用数。没有可用材料的角色记录资料不足。实际调用数、冻结输入及已收回证据可在研究完成后逐项核对。

| 看到的结果 | 怎么读 |
| --- | --- |
| 未发送 | 本地没有这次外发记录。可查看授权、资料与预算情况。 |
| 已发送，用量未知 | 工作台已经发出请求，供应商未提供完整计量。已收到的部分继续显示。 |
| 协议已接受 | 返回内容的结构、任务归属和引用已通过相应校验。 |
| 字面表述与来源相符 | 可以对照所引用摘要的原文，或具体日期和标的的收盘价、成交量。 |
| 待人工核对 | 该断言的表述超出自动对照范围，打开所引材料自行复核。 |

## 把一次研究交给 Codex

**直接在本机运行。** 安装本项目的 wheel 和 Codex CLI，使用自己的 Codex 账户登录。CLI 需支持结构化输出、只读运行及技能上下文隔离，本次实测的客户端版本记录在下方回执中。如果当前 Codex 登录环境含全局 `AGENTS.md` 或 `AGENTS.override.md` 指令，请使用已单独登录、全局指令为空的研究环境，或使用自己的 MCP 客户端领取同一授权。执行器在领取前检查这两个文件的元数据。此时发现问题，授权仍可使用。如果领取后、本机模型启动前出现新的全局指令，本次执行会以失败结束并留下回执。以允许外部调用的模式运行 Finathink。先选一般研究、因子挖掘或回测检验方法，再核对包指纹、时间和字节上限，勾选授予一次执行。内置执行器对三种方法均生成研究计划。需要提交因子公式的客户端可使用下文的手工因子提案回传。将页面生成的完整命令复制到本机终端。

```text
finathink-codex --run --url http://127.0.0.1:8765 --job <任务编号> --operation <执行编号>
```

命令领取授权后，将冻结材料交给独立的只读 Codex CLI。客户端使用临时目录，关闭本机技能清单和项目指令的注入，单次会话仍包含 Codex 自己的运行信息，例如临时目录、日期、时区和 shell。返回方案要给出假设、验证方法、否证条件、局限和包内证据引用。工作台计算摘要，核对原任务和证据后保存。一次领取占用原研究的一份执行额度。外部客户端自行管理对模型服务的请求、重试和计费，回执将它们的实际次数与用量保留为未知。运行期间可在页面取消，回传冲突、已过期和来源变化都会留下可查状态。同一交接在领取后重启也可查询原记录。[Codex 配置参考](https://developers.openai.com/codex/config-reference/)

**手工交接。** 下载原始 JSON 给自己的研究客户端。将客户端返回的 `method-result.v1` 粘贴到「手动回传」。JSON 内的数值与内容指纹按原文传递。研究计划和因子提案按各自的结构校验，认可的产物可在该任务的交接详情中阅读。

**通过 MCP 客户端接入。** 将同一命令去掉 `--run` 作为已获授权的 stdio 服务，保留指定的本机地址、任务与执行编号。工具 `read_research_task` 领取材料，`submit_research_plan` 提交方案，`report_research_failure` 登记失败。连接和列出工具只做协议发现。由客户端按其自己的工具权限设置访问。[MCP stdio 传输规范](https://modelcontextprotocol.io/specification/2025-06-18/basic/transports)

## 复核发布证据

| 验证对象 | 发布时的证据 |
| --- | --- |
| OpenAI-compatible 与 DeepSeek-compatible | 两种适配器经过受控传输、真实本机队列、角色映射、可追溯原句与数值核验、超时、取消、迟到、冲突和重启回归。两种用户自有账户均待实测。 |
| 独立 Codex CLI | 使用内置合成快照和已登录客户端实际生成并回传一份研究方案。收据记录包摘要、类型、研究方案正文和引用。外部账户的计费用量未知。 |
| 研究结论 | 回传收据验证研究方案的类型和证据归属。策略是否有效须另用冻结的样本外检验。 |

GitHub Release 同时提供 `finathink-codex-synthetic-receipt.json` 和 SHA-256 校验值，便于离线核对这次实际生成的研究方案。[真实 Codex 合成回传记录](verification/phase34-codex-synthetic.json)

从源码目录使用安装了本项目的环境可以重复以下验收。第一条使用临时离线工作区，第二条授权一次合成材料的独立 Codex 调用，第三条在运行中的研究台授权所选模型配置使用同一合成样例。输出为脱敏 JSON。

```sh
python scripts/check_model_workbench.py
python scripts/check_model_workbench.py --codex
python scripts/check_model_workbench.py --url http://127.0.0.1:8765 --provider YOUR_PROFILE_ID
```
