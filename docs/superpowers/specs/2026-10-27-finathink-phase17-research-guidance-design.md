# Phase 17：数据就绪、首次研究与解释

日期：2026-10-27。执行依据：用户确认 `FINATHINK_NEXT_IMPROVEMENTS_2026-10-27.md` 的 Phase 17，授权自主实施、测试、修正和发布。保持已确认的蓝白外壳和 Phase 16 动效。

## 目标与实现选择

把“连接自己的数据 → 冻结快照 → 检查 → 明确提交 → 阅读报告”连成清晰路径。就绪检查只读本地快照和配置；不获取外部数据、不启动任务、不调用模型。使用现有 Python 服务、原生 HTML/JS 和队列，新增小型投影模块；相比单做前端提示，它可由 API 与浏览器共同验证；相比另建向导系统，它保留唯一任务/快照事实源。

## 数据就绪合同

新增受 CSRF 保护的 `POST /api/research/readiness`，接受与提交相同的研究输入（无需 idempotency_key）。返回 `research-readiness.v1`、输入摘要指纹、`can_submit`、`READY/NEEDS_REVIEW/BLOCKED`、有序检查项及各自可定位的修复链接。检查：已保存快照完整性、标的、研究日期、至少四条 OHLCV、每日最多一条、整体截止 PIT、逐根历史可用性、单位、停牌字段、行业覆盖、固定方法依赖、模型配置/逐次授权/材料时间、问题和资源预算。所有错误只返回受控中文，不回显私人材料、凭证或内部路径。

阻断项来自现有运行合同；缺少单位声明、行业或停牌字段等尚不构成现有基线输入错误的事项显示“待核对”，不可伪称已验证真实可交易性。`can_submit` 只表示可以开始固定的纸面研究，不表示因子有效或可以交易。未支持的方法不会因自然语言模板而成为已实现策略。缺少角色材料逐项列出，不推断基本面、新闻或情绪。

显式数据获取可附带价格币种与成交量单位声明，冻结在快照 provenance 中；声明不转换数值，未知保持未知。选择字段映射、单位说明、重新获取快照、研究截止日、模型配置和材料表单的入口都可定位。检查必须和相同输入绑定；修改后旧检查失效，晚到响应不能覆盖新输入。提交按钮先用当前输入做检查，阻断时无任务入队，非阻断时沿用原幂等提交。

## 首次使用与恢复

页面开头显示准备数据、核对输入、运行、读报告的进度与下一步，保留明确的 SAMPLE 演示分支。快照摘要显示来源模式、标的、行数与日期；完整指纹按需展开。默认离线配置无需模型 Key；配置保存不代表已试连。

观察现有任务可在刷新/服务重启后从 URL 和持久记录恢复，不创建新任务。提供“沿用基础输入”以显式填回快照、标的、截止日、问题和预算；不会修改原任务，付费授权取消，材料需重新确认，重新提交仍是一个新任务。排队、重试等待、超时、取消、发布损坏均有不同说明与下一步，自动重试只由既有 worker 规则控制。

## 研究解释

服务端从已验证任务、checkpoint 和报告生成 `research-explanation.v1`：结论、依据、分歧、适用条件、下一步、因果阶段列表。每阶段区分需要的输入、实际状态、已记录事实和阻塞原因。没有真实阶段时间时只呈现顺序，不能虚构耗时。

有报告才链接对应报告证据；链接限定当前运行及已有章节/锚点。数值只复述服务器指标，未完成或发布失败不得显示完成结论和旧指标。经理分歧原样保留，材料不足不同于无分歧。纸面意向等待下一观测不能说已成交。因子实验与固定基线清楚区分。

新生成的普通离线报告也以结论/证据/条件/下一步开头，技术 JSON 保持折叠；旧报告字节不变。因子专用报告保留已有九步证据结构。

## 验收

- 真实 API：空/缺失/损坏快照、错误标的、未来或未知 PIT、历史延迟、重复日、缺行、单位/停牌未知、模型无授权、坏材料和预算均有可执行提示；无付费或排队副作用。
- 真实浏览器：保存用户接口、显式获取受控本地响应、检查、提交、spawn 完成、报告、刷新恢复；SAMPLE 路径仍可用。晚到检查、编辑失效、重复提交、失败恢复、切换历史任务不串结果。
- 解释：成功、失败、超时、排队、重试、取消；证据链接、分歧、安全转义和未知值；旧报告哈希不变，新报告无 JS 可读。
- 1440×900、1920×1080、375×812、键盘与减少动态效果；检查截图和前端测试，全量 Python/构建/质量门禁及独立整分支审查。

## 本轮边界

不增加供应商 SDK，不购买账号，不自动调权，不发送用户真实接口请求。自动化验收使用明确合成输入与受控测试传输；真实账号质量评估属于 Phase 18。Phase 17 依照现有内核解释就绪范围，不将声明升级成外部验证。
