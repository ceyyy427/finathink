# 复盘、学习审核与版本化复跑

打开本地应用的“复盘与学习”（`/research/learning`），按“原研究 → 后续观察 → 修改预览 → 审核 → 按版本复跑”操作。已有研究、数据和报告继续使用同一组运行记录与指纹。

## 准备一份可复核的复盘

1. 在“研究任务”完成普通纸面研究，保留完整报告。
2. 通过自己的通用数据连接获取后续数据，保存为不可变快照。快照可以包含原历史，也可以只包含后续观察；与原历史重叠的价格、量额、可用时间、行业和停牌状态必须一致。
3. 在复盘页选择原运行、后续快照和 UTC 截止日，再生成预览。页面持续显示原始、后续及估值数据的 `SAMPLE`、`SYNTHETIC` 或捕获模式。

观察沿用原报告的目标配置、入场费用、滑点、容量和下一观察成交规则。原研究截止日之后的首个执行观察为起点，其后固定 **5 个观察间隔**估值，因此至少需要6条后续观察。不是5个交易日，也不随后来价格延长窗口。原执行观察停牌、无容量或未满足可用时间而没有成交时，正仓位意图保持待执行，不产生已成交学习结果。

估值使用真实模拟持有数量、剩余现金和归档末价。净变动包含入场费用、滑点；它是固定期末的纸面盯市结果，不是假设平仓后的收益或可变现报价。价格和现金沿用用户输入声明的共同单位。

服务器验证快照、报告 manifest、原配置和数据指纹；有效截止时刻取请求日期日末与服务器当前时刻的较早值，并保存计算时刻。因此当天晚些时候才发生或才可用的观察，也不会提前成为已知结果。服务器拒绝未来复盘日期、未到期窗口及历史修订。因子实验的验证或最终测试不能通过此入口成为学习来源，保持留出集隔离。同一原运行的相同请求幂等返回原复盘；同一标的、决策日、信号与配置也不能通过复制运行重复计入学习。

## 先看证据，再决定修改

复盘并列显示原研究假设、计划仓位、实际纸面成交、固定期末估值及成本，不虚构原研究没有给出的目标收益预测。1、3、5观察标签跨度的 IC 由现有因子评估器计算，属于已知数据上的描述性衰减诊断；样本不足时保留未知，不把它当成新的独立样本外验证。

当前可审核规则为明确的保守启发式：

- 固定观察期出现纸面净损失时，提议将当前动量信号预算乘数缩小10%，下限0.1。
- 同时提议将经验 CVaR 上限缩小10%，下限0.01。
- 正收益、零敞口或已经达到两个下限而没有数值修改时，保留原配置，不创建空版本。

这是一套有边界、可审核的研究调整规则，不是统计上已经证明有效的自学习模型。信号预算乘数在既有风控约束之后作用，批准的数值实际进入回测与纸面配置；仅把参数写入报告不算应用。

预览列出原值、建议值、父版本和预览指纹。填写审核依据后可批准或拒绝；批准前需要确认已核对证据。服务器核对提交时的预览指纹，拒绝过期预览。一次审核决定不可覆盖；相同决定与依据可安全重试，并发的相反决定只保留一个。拒绝记录保留，且不产生可执行配置。

## 版本、回滚与新运行

批准产生一个新的不可变 `VersionedResearchPolicy`。`policy_ref` 是该版本指纹，实际执行参数另有 `runtime_fingerprint`；二者通过父版本、提案、结算、账本和数据引用绑定。审核不会改变全局默认值，也不会覆盖原研究。

在复跑区选择原研究、配置版本、快照和运行截止日。可选新版本，也可选择基准或旧版本进行回滚比较。每个新提交有独立运行与报告；相同提交标识不会重复排队。响应不确定或任务运行中时，页面重用原标识；已确认取消或失败之后，再次显式提交使用新标识，保留旧失败记录并创建新运行。复跑默认走本地确定性流程，原任务的付费模型外发授权不被继承。

批准可用时间保守取审核 UTC 日末。请求截止日不能早于批准日期；若研究信号早于配置可用时间，页面与离线 HTML 报告标为“回溯比较”。这种运行可以检查参数变化，但不能重新结算为该配置生效后的新学习证据。对生效后真实新增的观察，仍按同一可用时间和固定观察期规则检查。

版本化复跑固定的是配置和输入，不把不同引擎内核伪装成同一个实现。报告保留实际参数与方法指纹；保留对应代码、依赖和快照可复核旧运行。内核指纹变化时，系统拒绝用当前默认值静默解释旧配置。

## 本地持久化与恢复

审核控制状态与版本索引使用现有队列 SQLite；提案、准入记录和批准预览沿用 `LearningProposalStore`。原运行与报告事实仍来自 `RunRepository` 和校验后的 manifest。

数据库事务串行化并发审核。若准入文件已经落盘、而版本索引写入中断，读取时按同一准入和预览重建同一版本，不撤销决定、不生成第二份批准。重启后可读取复盘、版本和报告。列表显示最近100次复盘及基准与最近100个批准版本，旧记录仍可按其稳定引用读取。

## 接口

所有写请求使用本地页面的 `_csrf`，不接收模型 Key、原始策略代码或客户端计算的收益、权重修改。

| 操作 | 方法与路径 | 关键字段 |
| --- | --- | --- |
| 复盘列表 | `GET /api/research/learning` | `reviews` |
| 生成复盘 | `POST /api/research/learning` | `run_id`、`evidence_snapshot_ref`、`as_of` |
| 读取复盘 | `GET /api/research/learning/{review_id}` | 证据、预览、审核、版本引用 |
| 显式审核 | `POST /api/research/learning/{review_id}/decision` | `decision`（`APPROVED` / `REJECTED`）、`expected_preview_fingerprint`、`rationale` |
| 可选配置 | `GET /api/research/learning/policies` | 基准、批准版本、实际参数与父版本 |
| 创建复跑 | `POST /api/research/learning/rerun` | `idempotency_key`、`run_id`、`policy_ref`、`snapshot_ref`、`as_of` |
| 普通任务引用版本 | `POST /api/research/jobs` | 原任务字段加可选 `policy_ref` |

运行进度、取消和报告继续走既有 `/api/research/jobs/{job_id}` 与报告入口。完整离线报告含所选配置引用、实际参数指纹、父版本、批准可用时间、复跑原运行和回溯标识。
