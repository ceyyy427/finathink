# 基于材料的模型研究

Phase 6 对应产品路线的 Task 5。研究问题、经授权的材料摘要、数据与政策指纹、可引用证据索引，一起进入模型上下文。模型给出观察和待验证假设；回测、风险指标、仓位和纸面执行仍由服务器的固定低频策略计算。

## 从页面开始

1. 在启动本地应用的环境中配置自己的模型 Key，记住环境变量名称。也可通过配置 API 指定已有系统 Keychain 引用。不要把 Key 值填进研究问题或材料。
2. 启动应用时不启用 `--offline`。开启该选项时，新增及恢复的在线任务都会被阻断；保存模型配置本身不发出请求。
3. 打开“模型接口”，填写配置标识、兼容协议、模型标识、HTTPS 基础地址或完整 `/chat/completions` 地址，以及环境变量名称。可给不同角色指定不同模型。
4. 回到“研究任务”，选择已冻结的快照、标的、截止日及模型配置。按需补充下述角色材料。
5. 勾选授权，确认将问题、标的、最近最多 16 条行情和所填摘要发送给所选服务，并承担调用费用，然后提交。
6. 查看五类角色的材料状态、观察、调用记录、经理综合、分歧、待验证假设，以及独立计算的数值结果。完成报告可离线阅读，重启后仍可查看。

模型标识按有界字符串校验，不维护供应商可用模型目录。用户需以自己的服务实际支持的模型为准。兼容协议也不代表每个第三方端点已经验收。

## 角色与材料

| 角色 | 输入 |
| --- | --- |
| `technical` | 所选快照的实际价格、成交量、可用时间，以及用户补充的技术摘要 |
| `fundamentals` | 用户授权的基本面摘要 |
| `sentiment` | 用户授权的情绪摘要 |
| `news` | 用户授权的新闻摘要 |
| `learning` | 用户授权的既往学习或复盘摘要 |
| `research` | 上述材料、各角色已校验的观察、资料不足状态和证据索引 |

除技术材料由行情快照提供外，其余资料不从行情推测或自动抓取。没有某类材料时显示 `INSUFFICIENT_DATA`，该角色不调用模型。允许形成明确标注的部分分析，不把“运行完成”解释为五类材料齐备。

材料为 JSON 数组，最多 16 条，每条摘要最多 2000 字。示例：

```json
[
  {
    "role": "news",
    "instrument": "AAA",
    "summary": "公司公告计划新增一条生产线，投产时间仍需后续确认。",
    "source_label": "用户整理的公司公告摘要",
    "observed_at": "2026-09-01T08:00:00Z",
    "available_at": "2026-09-01T09:00:00Z",
    "authorized": true
  }
]
```

摘要属于用户提供的材料，不是系统认证的事实。时间必须包含时区，满足观察时间不晚于可用时间、可用时间不晚于研究截止日（UTC 当日结束）。标的必须匹配本轮研究。缺少授权、未知或未来可用时间、凭证/路径等敏感材料会被拒绝。来源使用非敏感标签，不在摘要中粘贴 Key 或私有地址。

## 上下文与引用边界

`ResearchContextBundle` 是输入的私有投影，不是新的行情来源。它绑定 run、snapshot、policy、as-of、role；证据引用只能来自该角色本轮索引。经理使用各角色材料的并集，并再次核对已有报告的引用。

默认每份上下文上限 32 KiB，HTTP 请求上限 256 KiB、响应上限 1 MiB；模型输出请求上限 1024 个生成 token。上下文按字节计量，不声称是精确 tokenizer 估算。供应商返回的合法整数用量映射为 `usage.input_units`、`generated_units`、`total_units`；即使研究内容未通过校验，已收到的用量也独立保存，未收到的部分保持未知。字节预算计量 JSON 输入/输出，不是操作系统总网络流量配额；任一共享资源预算耗尽后，不再允许新增请求或发布成功报告。

模型仅返回受校验的 JSON 观察，没有工具执行、任意代码或修改数值策略的权限。分析师必须给出非空观察；经理还须明确给出非空待验证假设及分歧数组。不存在于本次索引的引用、空观察、截断输出、内容过滤结果和非法结构不能变成有效报告。引用校验只能证明归属、授权与时点，不能证明自然语言推断的真实性。

## 调用、隐私与恢复

- 配置保存仅包含端点和凭证引用；凭证值只在适配器内部、临近请求时读取。队列只保存私有输入引用，报告不含完整上下文、端点或 Key。
- 已提交任务冻结当时的模型配置和材料。修改或移除配置不会追溯撤销已排队任务；需要取消对应任务，或撤销其实际凭证。凭证值不被冻结。
- 在线任务只有一次 worker 尝试、每个模型请求只有一次 HTTP 尝试，不自动重放未知的付费副作用。瞬态失败需用户新建提交。
- 默认最多 6 次模型调用（五个角色加经理）；缺资料的角色不消耗调用。并行线程共享持久化任务的调用/字节预算及墙钟约束。
- HTTPS 使用证书及原主机名校验，DNS 结果须为公开地址并固定到实际连接；不使用环境代理，不跟随重定向，不访问私网或元数据地址。
- 私有 SQLite 调用日志在请求前落盘，再记录出站意图和最终结果。它保存绑定到本任务的角色、模型、上下文指纹/字节、耗时、状态及已返回用量；不保存 Key、端点或原始材料。成功报告、失败任务、取消及重启后的任务页均可查询。
- 出站意图是本地记录，不证明服务实际收到或计费。进程中断且结果未确认时显示 `UNKNOWN`，用量为空而不是零；费用应查用户的服务账单。任务累计计量可能只回传了部分，不能替代逐次日志或费用结算。
- 检查点使用稳定模型指纹引用，避免把命名空间模型名误当文件路径。在线研究档案与离线档案使用相同的只读运行状态合同。

## Codex 外部执行

现有 Codex 桥接仍是外部派发/回传合同，不会自动调用当前聊天或桌面会话。生成 handoff 不等于完成研究，必须由外部执行端回传，并通过既有绑定、幂等和状态校验。本期首先贯通兼容 Chat Completions 协议，不把其他原生协议或桌面会话自动化算作已完成。

## 验收记录

| 范围 | 本次状态 | 证据边界 |
| --- | --- | --- |
| 上下文、PIT、授权、跨运行/角色引用 | 自动化验证 | 使用受控材料，覆盖拒绝路径 |
| 兼容协议、预算、HTTPS 策略 | 自动化验证 | 只替换远端 DNS/TLS I/O；不使用真实 Key |
| 页面 → HTTP → 独立 spawn → 兼容传输 → 引用校验 → 报告/重启 | 自动化验证 | 受控模型对端，不是供应商实测 |
| 用户自己的服务、账号权限、模型输出质量及真实费用 | `NOT_RUN` | 本次未提供并显式连接真实模型账号；不声称已完成供应商验收 |

用户连接后应显式跑一份可公开的最小材料，核对实际端点响应、模型路由、引用、调用用量、失败/取消和重启阅读，再记录为该用户连接的验收结果。不要复用离线合同测试结果替代这一步。
