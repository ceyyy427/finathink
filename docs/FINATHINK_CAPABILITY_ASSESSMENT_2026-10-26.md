远端基线：GitHub `main`，`f2520b9e68c543c236fc0f999ee0e68a110c0ff1`，即 PR #9 的合并提交。

## 当前判断

Finathink 已具备本地研究内核、可复现的离线研究组件、后台任务基础和研究界面。
下一步是将这些组件接成用户能够从页面完成并在重启后继续使用的研究流程。
界面 Phase 1–3 的交付，不能解释为真实模型、真实数据和后台任务已在默认产品路径全部贯通。

## 本次确认的关键缺口

1. **默认研究页仍使用 fixture。** `local_app.py` 的 `/api/research/series` 和
   `/api/research/workbench` 调用无参数的 `build_research_payload()`；没有按用户选中运行读取结果。
2. **研究列表仍是会话内索引。** `LocalApplication._research_runs` 从空字典开始，
   `register_research_run()` 显式注册结果；Overview 与对比依赖此字典。
   这与后台队列已持久化是两个不同层次，不能把队列恢复等同于页面研究历史恢复。
3. **研究对比路由缺少 AppShell。** 本次对 `/research/compare` 的路由探针返回 200，
   但正文没有 document、main 或 nav。应复用 `render_page()`。
4. **Overview 有重复初始化入口。** `overview.js` 和 `research.js` 都自动调用
   `mountOverview()`；应统一初始化并保证 chart resize/dispose 生命周期。
5. **Tooltip 的键盘路径不完整。** ECharts 在 `.overview-chart` 初始化时会移除原有
   子元素，而当前可聚焦条形位于这些元素中；需要独立保留按日数据表或原生按钮选择器。
6. **活动时间与研究时间混合。** Overview 将 run 的 `as_of` 直接用作活动日期，
   页头时间取固定样例事件日期；主题目前是 `source_kind`，学习热力仍是列表。
   应分别定义运行发生时间、数据截止时间、研究主题与学习行为。
7. **默认模型请求缺少研究上下文。** `provider_adapters.py` 请求发送 digest 和 role；
   模型无法由 hash 恢复数据。后续要传递明确授权的研究材料，并验证返回证据引用。
8. **浏览器门禁覆盖不足。** 当前 CI 未配置独立 Node 构建/前端测试/browser job；
   浏览器用例缺少二级对比页与真实主题数据场景。已有截图和资源/DCL 上限不等同于完整性能验收。

## 优化取向

可选择继续扩展界面、优先扩展算法，或先贯通用户研究主流程。
建议第三种：先统一数据快照和运行记录，让页面提交的研究实际消费同一份数据、
由后台执行、产出可恢复报告，再扩展模型研究深度与因子实验规模。
这样每新增一个算法或角色，都能在同一条用户流程中被检验。
