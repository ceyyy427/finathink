# 样本评估、成对复跑与本地维护

打开“复盘与学习”，顶部的“样本评估”跳到新工作区。“本地任务维护”位于系统导航，也可从复盘页进入。沿用当前工作区的快照、报告、审核记录和后台任务。

## 从结算到可审核建议

1. 先在原流程选择已完成的普通纸面研究和后续观察数据，生成固定五观察间隔的结算记录。
2. 在“样本评估”选择一条普通复盘作为范围锚点，填写开始日和证据截止日。系统收集同标的、同父配置的全部候选，最多200条；不会让调用者挑选亏损记录的 ID 列表。
3. 系统重建每条结算，核对原报告、数据、配置和事件摘要。按冻结代码、数据模式和成本规则筛选，并排除重复经济信号、重叠窗口、未成交、未知结果和截止时尚不可用的证据。
4. 阅读合格数量、覆盖范围、收益分布、亏损/非亏损/零收益、最多20个反例，以及逐项排除原因。
5. 达到固定门槛后才能“生成建议并打开审核”。只有批准才创建新政策版本；拒绝和继续观察均保留原配置。

固定门槛：至少20个合格窗口、平均纸面净收益小于零、亏损比例的双侧95% Wilson区间下界大于0.5。满足时才建议当前信号预算和 CVaR 上限各收缩10%，保留0.1和0.01下限。无数值变化时不创建空版本。计算采用 [NIST 的 Wilson 区间公式](https://itl.nist.gov/div898/handbook/prc/section2/prc241.htm)。

这些是事先固定的工程规则。窗口不重叠只代表操作上的分离，不保证统计独立；区间依赖独立同分布的二项观察假设，相关市场序列可能低估不确定性。日期范围由用户选择，仍可能有选择偏差。输出是历史纸面描述，不是未来盈利概率，也不是经过市场校准的结论。

单次结算仍可用于明确的探索性试验。批准时需要额外确认探索属性；API 必须传 `allow_exploratory: true`，审核者模式记录为 `local-user-exploratory`。历史已批准版本保持有效。样本建议与因子观察分别保留各自的证据类型。

评估按内容摘要冻结保存。新证据到达后应重新评估；不会改写旧评估的日期范围和证据集合。生成建议前再次核验证据。截止日期不能在未来，记录在截止时尚未被观察，也不会被回填成当时已知。

## 批准前后成对复跑

选择已批准的数值配置复盘、共同快照和共同截止日，创建两项离线任务：父版本与新版本。两边绑定相同标的、问题、数据、日期及代码/依赖身份，只有政策不同；都受原有资源预算和独立 worker 管理。

- “尚有任务未排队”：已保存成对绑定，可显式继续；GET 和刷新不创建任务。
- “后台运行中”：从任务详情查看进度或取消；完成后点击刷新状态。
- “成对结果已校验”：两份报告与绑定均通过检查，显示新版本减父版本的有限数值指标差值。
- “需要检查子任务或报告”：失败、取消、产物损坏或身份失配；不显示伪造的成功比较。

中断发生在任意一边排队附近时，确定性提交标识避免重复任务。代码或依赖发生变化时，旧绑定不能继续排队，应创建新的成对记录。已完成的旧报告仍可按其冻结身份读取。

复用学习期或批准前数据会标为“回溯比较”。较晚窗口也只是描述性研究，不能凭一次差值宣称策略有效。复跑不自动结算或产生学习更新。

## 本地任务维护

维护页显示当前工作区的队列数量、过期租约、退避与取消情况、最近最多100项任务的已保存阶段耗时，以及本地磁盘余量和数据库/WAL大小。未采集的运行进程内存和 CPU 显示未知。页面读取不会恢复租约或启动研究；取消和恢复沿用已有明确操作。

历史列表每页最多100条，默认20条。首次读取冻结 SQLite 行号水位，以创建时间和任务ID翻页；随后新增任务不挤动同一轮翻页。返回第一页可以开始新的读取。列表的 `NOT_CHECKED` 表示仅有元数据，打开任务详情才检查完整报告。

报告完整性校验使用每个仓库实例独有的64项、2秒成功缓存。每次命中仍检查文件路径、链接和文件设备/inode/大小/修改时间/变更时间；改变即失效，失败不缓存。报告树内的符号链接拒绝，树外已有系统路径别名保留并跟踪。普通同大小修改并还原mtime仍会由ctime变化失效。缓存基于可信本地文件系统，不承诺抵御能伪造元数据的敌对管理员。

## 运行本机基准

在仓库根目录、已安装项目依赖的 Python 环境运行：

```sh
python3 scripts/benchmark_phase20.py --jobs 1000 --repetitions 20 --output /tmp/finathink-phase20-benchmark.json
```

基准使用1000条 SAMPLE 待运行任务、20次列表/报告读取、4线程并发读取、实际两任务 spawn、完成后的重开，以及单独标注的可控时钟租约恢复。JSON包含平台、Python/SQLite、样本规格和实际时间，不访问用户外部接口。

本轮 macOS/ARM64、Python3.13.7、SQLite3.50.4：完整列表平均51.25毫秒，轻量列表6.44毫秒；冷报告读取5.22毫秒，暖缓存3.91毫秒。优化前独立基线分别为55.76和4.30毫秒。冷校验增加元数据检查开销；这些是本机工作负载的结果，不代表所有设备或大规模生产容量。
